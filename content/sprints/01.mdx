## 0. Antes de começar — leia isto

Você já mandou um agente fazer alguma coisa e ele fez **errado de um jeito que deu prejuízo**? Apagou arquivo, alterou banco, rodou comando perigoso, criou bug silencioso?

Esse Sprint resolve esse problema na raiz.

**A grande virada de chave:** você vai parar de pensar no <Termo k="agente">agente</Termo> como "o cara que faz" e começar a pensar nele como "o cara que **propõe**". Quem faz é outra coisa — uma camada <Termo k="deterministico">determinística</Termo> que **você controla**, que **você lê**, que **nunca alucina**.

Essa camada se chama <Termo k="harness">harness</Termo>. É o cinto de segurança do agente.

<Diagrama legenda="Fluxo básico do harness — o agente nunca toca no sistema direto">
{`flowchart LR
    A[Você] -->|pede algo| B[Agente LLM]
    B -->|propõe ação| C{Harness}
    C -->|libera| D[Sistema Operacional]
    C -->|bloqueia| E[Devolve erro ao agente]
    E -.->|re-tenta| B`}
</Diagrama>

No fim do Sprint 1, esse diagrama acima estará **funcionando no seu computador**.

## 0.1 Como este curso funciona — leia ANTES de tudo

Você é o **<Termo k="arquiteto">arquiteto</Termo>**. Seu agente (Claude ou Gemini) é o **<Termo k="pedreiro">pedreiro</Termo>**. O harness é o **<Termo k="fiscal">fiscal</Termo>**.

| Papel | Quem | O que faz |
|---|---|---|
| 🏛️ Arquiteto | **Você** | Lê, especifica, encomenda, inspeciona, decide. |
| 🧱 Pedreiro | Seu Claude/Gemini | Recebe pedido, escreve o código, reporta. |
| 👮 Fiscal | Harness + <Termo k="learning-gate">Learning Gate</Termo> | Valida deterministicamente se o trabalho está OK. |

**Você nunca vai digitar código.** Você vai:
1. Ler o conceito do <Termo k="spec-manual">Spec Manual</Termo>.
2. Copiar um **template de pedido** que o Manual te dá pronto.
3. Colar no seu Claude/Gemini.
4. Quando ele devolver, **abrir o arquivo no editor** e percorrer uma **<Termo k="checklist">checklist</Termo>** (sem precisar entender cada linha — só verificar pontos específicos).
5. Se a checklist falhar, devolver ao agente com instruções precisas que o Manual também te dá.
6. Quando passar na checklist, rodar o **Fiscal** (`npm run gate`).
7. Escrever uma **<Termo k="reflexao">Reflexão</Termo>** curta sobre por que o que você acabou de construir importa.

<Aviso variante="dica" titulo="Por que isso funciona">
Isso é meta. **O que você aprende no curso (orquestrar agentes) é exatamente o que você FAZ durante o curso.**
</Aviso>

## 1. Os 3 conceitos-âncora

### 1.1 Vibe coding vs Engenharia de Harness

| <Termo k="vibe-coding">Vibe coding</Termo> | Engenharia de Harness |
|---|---|
| "Vai lá, faz aí." | "Você propõe, eu valido." |
| Quando dá errado, você re-prompta. | Quando dá errado, você aperta uma regra. |
| O agente é a estrela. | O agente é um motor. A estrela é o harness. |
| Funciona em demo, falha em produção. | Funciona em produção exatamente como funcionou no teste. |

<Aviso variante="dica" titulo="A frase que você vai repetir até dormir">
**"Cada erro do agente é uma falha de design do MEU harness, não do modelo."**
</Aviso>

### 1.2 Por que o agente fica "burro" no meio da conversa

Você já notou que depois de muita troca de mensagem, o agente começa a esquecer regras, repetir bobagens, ou ignorar coisas que você disse no começo?

Isso tem nome técnico: <Termo k="context-rot">Context Rot</Termo>.

Sem entrar em matemática: o <Termo k="llm">LLM</Termo> tem uma "janela de atenção". Ele lembra muito bem do **começo** e do **fim** dessa janela, e esquece o **meio**. Esse efeito se chama <Termo k="lost-in-the-middle">"Lost in the Middle"</Termo>.

<Diagrama legenda="O LLM presta atenção nas pontas, esquece o meio">
{`flowchart LR
    subgraph Janela["Janela de atenção"]
        A["Começo<br/>👁️ atenção alta"] --> M["Meio<br/>😵 atenção baixa"] --> F["Fim<br/>👁️ atenção alta"]
    end`}
</Diagrama>

**O que isso muda no que você faz como arquiteto:**
- Regras críticas vão em **<Termo k="claude-md">CLAUDE.md</Termo>** (no começo) ou em **<Termo k="hook">hooks</Termo>** (fora do contexto do agente).
- Conversas longas → **resumir e reiniciar** (vamos ensinar no Sprint 4).
- Não jogue 90 mil tokens de documentação no prompt do agente achando que ele vai "ler tudo".

### 1.3 Tools, Skills e MCP — a confusão que custa caro

Você vai ouvir esses três termos o tempo todo. Não confunda:

| Termo | Analogia | É |
|---|---|---|
| **<Termo k="tool">Tool</Termo>** | Chave de fenda | Uma função atômica. Faz UMA coisa. |
| **<Termo k="skill">Skill</Termo>** | Receita de bolo | Combina várias tools numa ordem certa. |
| **<Termo k="mcp">MCP</Termo>** | Padrão USB-C | Protocolo aberto que conecta agentes a ferramentas. |

## 2. O Modelo Mental Central: <Termo k="proposal-engine">Proposal Engine</Termo>

<Diagrama legenda="Sequência completa: usuário, agente, harness, sistema">
{`sequenceDiagram
    participant U as Usuário
    participant A as Agente (LLM)
    participant H as Harness (você projetou)
    participant S as Sistema

    U->>A: "Apague os logs antigos"
    A->>H: Proposta: rm -rf /var/log
    H->>H: Verifica regras determinísticas
    H-->>A: BLOQUEADO — motivo: rm -rf fora de scope
    A->>H: Proposta: find /tmp/logs -mtime +30 -delete

**O agente nunca toca no sistema diretamente.** Sempre passa pelo Harness. O Harness usa regras escritas em **código tradicional**, sem IA. Determinístico. Auditável.

<Aviso variante="sucesso" titulo="Por que isso funciona">
O LLM é probabilístico (pode errar). O Harness é determinístico (sempre faz a mesma coisa para a mesma entrada). Misturar os dois te dá **inteligência do LLM + segurança da programação clássica**.
</Aviso>

## 5. Lab A — Seu primeiro Hook: bloqueio de comandos destrutivos

<Aviso variante="info">
**O que você vai conquistar:** seu repositório terá um Hook em `.claude/hooks/01-bloqueia-comandos-destrutivos.mjs` que IMPEDE qualquer agente de rodar `rm -rf /` ou `sudo`.
**Você não vai escrever este Hook.** Você vai encomendar ao seu agente e validar.
</Aviso>

### 5.1 Por que isto importa

O LLM é probabilístico. Em algum momento ele vai tentar fazer algo perigoso — porque alguém injetou um prompt malicioso (<Termo k="prompt-injection">prompt injection</Termo>), porque ele alucinou, porque entendeu errado. Sem este Hook, ele consegue. Com este Hook, **o sistema operacional NUNCA vai sequer receber o comando perigoso.**

### 5.2 O contrato do Hook

<Diagrama legenda="Fluxo do Hook 01: bloqueia padrões perigosos antes de chegar ao sistema">
{`flowchart LR
  A[Agente quer rodar comando] --> H{Hook 01}
  H -->|bate com padrão proibido| B[BLOQUEIA<br/>devolve 'deny' ao agente]
  H -->|tudo limpo| L[LIBERA<br/>sistema executa]`}
</Diagrama>

**Padrões que o Hook PRECISA reconhecer e bloquear:**
1. `rm -rf` seguido de qualquer caminho absoluto (`/`, `/tmp`, `/etc`, ...)
2. Qualquer uso de `sudo`
3. Redirecionamento (`>`) escrevendo em `/etc/` ou `~/.ssh/`

**Padrões que NÃO podem ser bloqueados** (senão a vida do agente vira inferno):
1. `ls`, `cat`, `git status` e similares
2. `rm node_modules/foo.js` (caminho relativo, sem `-rf` em raiz)

### 5.3 Seu pedido ao agente

<PedidoAoAgente titulo="Lab A — encomenda do Hook 01">
{`Você está trabalhando no repositório learning-harness em D:\\Workout\\Estudo\\Harness\\learning-harness.
Leia primeiro o arquivo CLAUDE.md para entender as regras do projeto e o seu papel.

Tarefa: implementar o arquivo .claude/hooks/01-bloqueia-comandos-destrutivos.mjs

Requisitos do contrato:
- Hook em Node.js puro (.mjs), sem dependências externas além de node:process.
- Lê payload JSON pelo stdin (use process.stdin com for await).
- Extrai .tool_input.command com JSON.parse.
- Bloqueia (process.exit(2) + JSON com permissionDecision "deny") se o comando bater com algum destes padrões:
    * rm -rf em caminho absoluto (começa com /)
    * sudo (qualquer ocorrência)
    * redirecionamento (>) para /etc/ ou ~/.ssh/
- Caso contrário: libera (process.exit(0) + JSON com permissionDecision "allow").
- Comentários em português.
- Sem any, sem eslint-disable, sem @ts-ignore.
- Tamanho-alvo: entre 40 e 80 linhas.

Quando terminar, rode no terminal: npm run gate -- --sprint=1
E me reporte LITERALMENTE a saída que apareceu (não resuma).`}
</PedidoAoAgente>

## 7. Lab C — Sensor de typecheck

<Aviso variante="info">
**O que você vai conquistar:** Hook em `.claude/hooks/03-typecheck-pos-edicao.mjs` que **avisa** (sem bloquear) o agente quando ele introduz erro de tipo.
</Aviso>

### 7.1 Diferença crucial: Guard vs Sensor

|  | <Termo k="guard">Guard</Termo> (Hooks 01, 02) | <Termo k="sensor">Sensor</Termo> (Hook 03) |
|---|---|---|
| Quando dispara | **Antes** da ação | **Depois** da ação |
| Exit code | `process.exit(2)` (bloqueia) | `process.exit(0)` (nunca bloqueia) |
| O que faz | Impede execução | Reinjeta erro no contexto do agente |
| Analogia | Mordomo que barra na porta | Espelho que mostra mancha de café |

### 7.2 O contrato

<Diagrama legenda="Hook 03 — sensor: sempre exit 0, escreve no stdout para o agente">
{`flowchart LR
  A[Agente edita arquivo] --> Q{Termina em .ts?}
  Q -->|não| F1[exit 0 silencioso]
  Q -->|sim| T[Roda npm run typecheck]
  T -->|sem erro| F2[exit 0 silencioso<br/>sucesso é silencioso]
  T -->|com erro| W[Escreve erro no stdout<br/>com instrução em PT-BR<br/>+ exit 0 mesmo assim]`}
</Diagrama>

### 7.3 Seu pedido ao agente

<PedidoAoAgente titulo="Lab C — encomenda do Hook 03 (SENSOR)">

Requisitos:
- Hook Node.js puro (.mjs).

- Extrai .tool_input.file_path.
- Se NÃO terminar em .ts, sai com exit 0 sem fazer mais nada.
- Se terminar em .ts, roda execSync("npm run typecheck --silent", { stdio: "pipe" }).
- Se o typecheck passar: exit 0 sem imprimir nada (sucesso silencioso).

## 9. Lab D — O Motor Determinístico em código

<Aviso variante="info">
**O que você vai conquistar:** os arquivos `src/sprint1/agente.ts` e `src/sprint1/motor.ts` funcionando, com 8 testes automatizados em verde.
</Aviso>

### 9.1 Por que isto importa

Hooks vivem **fora** do código do seu app — interceptam o agente que está te ajudando a desenvolver. Mas o seu **app em produção** também terá um agente, e ele também precisa de freios. Esses freios vivem **dentro do código do app**, e o padrão é o mesmo: o agente PROPÕE, o motor DECIDE.

### 9.2 O contrato

<Diagrama legenda="Motor de Decisão dentro do app em produção">
{`flowchart TB
    A[Sua app chama o agente] --> B[Agente gera Proposta<br/>tipo, parâmetros, risco]
    B --> C{motor.avaliarProposta}
    C -->|regra bate| BL[Devolve 'bloqueado'<br/>com motivo]
    C -->|tudo limpo| EX[Devolve 'executado'<br/>SIMULADO no Sprint 1]`}
</Diagrama>
